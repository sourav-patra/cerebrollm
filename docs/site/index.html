An answer with a quote we re-read in your file, or Not in the sources.

cerebrollm searches your Markdown documents on your own machine, asks a local model to quote the line it relies on, then opens the cited file and checks the quote is there. If the check fails, you get no answer.

How it works

One program between you, your notes and local models. A PostgreSQL index, Ollama for embeddings and answers, and a reranker loaded from local files.

  1. Search. Keyword and vector search return the top 20 passages. Drafts are left out; trusted and recent notes rank higher.
  2. Rerank. A cross-encoder (a model that reads the question and a passage together) keeps the best 8.
  3. Generate. A local model gets the 8 passages, marked as data, and is asked for one quoted line with its path.
  4. Verify. cerebrollm re-reads each cited file. The quote must be in it, and the file must still have the sha256 recorded at indexing time.
  5. Gate. At least one citation verified OK: the answer is printed. Any other case: exactly Not in the sources.

Use it as a tool from an AI app or agent

cerebrollm is a fixed pipeline. It does not plan or loop on its own. An agent can call it: cerebrollm mcp is a read-only MCP server (MCP is the standard way AI apps call outside tools) with two tools, search and verify. Passages come back wrapped in <<<BEGIN RETRIEVED DATA>>> markers so the host can treat them as data.

claude mcp add --scope user cerebrollm -- \
  ~/.cerebrollm/venv/bin/cerebrollm --config ~/cerebrollm.toml mcp

A host that sends tool results to a cloud model sends your passages to that provider. What leaves the machine is listed in docs/DATA.md.

Install

Ubuntu 24.04, native or under WSL2. You need Python 3.12, Ollama running at 127.0.0.1:11434, and about 17 GB of disk.

  1. Clone the repository. 
    git clone https://github.com/sourav-patra/cerebrollm && cd cerebrollm
  2. Install the system packages once, with sudo. Check: /usr/lib/postgresql/16/bin/postgres --version prints 16.x. 
    sudo bash engine/setup/root-ubuntu.sh
  3. Create the virtual environment and the socket-only database. Check: the last line is USER SETUP DONE. 
    bash engine/setup/user.sh
  4. Pull the models. Check: ollama list shows both. 
    ollama pull qwen3-embedding:0.6b
ollama pull gpt-oss:20b
  5. Index your notes and ask. The README gives the configuration rule your folder needs and the one-time reranker download. 
    engine/bin/cerebrollm index
engine/bin/cerebrollm ask "a question your notes answer"

pip install cerebrollm gives the same commands without the clone; steps 2, 3 and 4 still apply.

Fund a measurement

Every proposed item in the release map has one acceptance check. Support pays for the hardware time and the work to run a check. The output is committed whether the result is good or bad.

A scale ladder

Index and query corpora of rising size on rented hardware, and publish recall and latency at each step. Today the measured ceiling is 13,627 chunks.

A larger public item set

Enough graded items to bound a 2% confidently wrong rate. The 35-item set bounds it only below 8.6%.

macOS and native Windows

Run the quick start and the test suite on each platform and record the logs. Both are untested today.

To fund one of these, or to offer hardware time, open an issue and name the check.
